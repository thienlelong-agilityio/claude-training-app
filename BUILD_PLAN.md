## 1. Objective & scope

Scaffold a runnable local **Next.js 15 (App Router) + React 19 + TypeScript 5 + Tailwind CSS** web app that copies the **Days 12–15 Cross-functional Capstone** section of the AI Tools Training portal.

- Folder name and npm package name: `claude-training-app`.
- Runs at `http://localhost:3000`.

### Scope rules (Baseline v1.0)

- Build **only** the features in this plan.
- Do **not** add: standup notes, Slack copy buttons, leaderboards, a real backend, a database, real Google OAuth, analytics, dark mode, i18n.
- Keep the completion storage as a **simple legacy boolean map** (`Record<string, boolean>`, e.g. `{ "day-12": true }`) in `localStorage`. This is on purpose: the repo is a baseline for later Capstone feature-expansion exercises.
- "Google sign-in" and "cloud sync" are **mocks** only (in-memory + `localStorage`). No network calls.

## Phase 3 — Storage, mock auth & cloud sync (`src/lib/progress.ts`)

### Rules

- **Pure TypeScript.** No React imports, no DOM types required, no `next/*` imports.
- Never touch `window` / `localStorage` directly at module load. Use a helper:

  ```ts
  function getDefaultStorage(): StorageLike | null {
    if (typeof window === 'undefined' || !window.localStorage) return null;
    return window.localStorage;
  }
  ```

  Every function that takes `storage?` falls back to `getDefaultStorage()`; if that is `null`, reads return the empty value and writes are no-ops.
- All `JSON.parse` calls are wrapped in `try/catch`.

### Required exports

```ts
export const STORAGE_KEY = 'training_progress';
export const AUTH_KEY = 'training_auth_user';

export type LegacyProgressMap = Record<string, boolean>;

export interface MockUser { name: string; email: string }

export interface StorageLike {
  getItem(key: string): string | null;
  setItem(key: string, value: string): void;
  removeItem?(key: string): void;
}

export interface CloudClientLike {
  isSignedIn: boolean;
  user: MockUser | null;
  remoteData: LegacyProgressMap;
  fetchAll(): Promise<LegacyProgressMap | null>;
  saveAll(data: LegacyProgressMap): Promise<boolean>;
}

export const DEFAULT_MOCK_USER: MockUser = { name: 'Learner', email: 'learner@example.com' };

/** Factory so tests get a fresh, isolated client. */
export function createMockCloudClient(initial?: Partial<Pick<CloudClientLike, 'isSignedIn' | 'user' | 'remoteData'>>): CloudClientLike;

/** App-wide default in-memory mock client. */
export const mockCloudClient: CloudClientLike;

export function loadLocalProgress(storage?: StorageLike): LegacyProgressMap;
export function saveLocalProgress(data: LegacyProgressMap, storage?: StorageLike): void;
export function loadAuthUser(storage?: StorageLike): MockUser | null;
export function saveAuthUser(user: MockUser | null, storage?: StorageLike): void;

export async function toggleDayComplete(
  dayId: string,
  isCompleted: boolean,
  deps?: { storage?: StorageLike; cloud?: CloudClientLike },
): Promise<LegacyProgressMap>;
```

### Behaviour

- **`loadLocalProgress`** — read `STORAGE_KEY`, `JSON.parse`. Return `{}` if the key is missing, the JSON is malformed, or the parsed value is not a plain object. Keep only entries whose value is a boolean (legacy-safe).
- **`saveLocalProgress`** — `setItem(STORAGE_KEY, JSON.stringify(data))`.
- **`loadAuthUser`** — read `AUTH_KEY`; return `null` if missing, malformed, or missing string `name`/`email`.
- **`saveAuthUser`** — if `user` is `null`, call `removeItem(AUTH_KEY)` (fallback: `setItem(AUTH_KEY, '')` when `removeItem` is not provided, and treat `''` as signed out in `loadAuthUser`). Otherwise write JSON.
- **`createMockCloudClient`** — in-memory object. `fetchAll()` returns a copy of `remoteData` when signed in, else `null`. `saveAll(data)` sets `remoteData = { ...data }` and returns `true` when signed in; returns `false` and changes nothing when signed out.
- **`toggleDayComplete`**:
  1. `const current = loadLocalProgress(storage)`.
  2. `current[dayId] = Boolean(isCompleted)` (keep `false` entries; do not delete keys).
  3. `saveLocalProgress(current, storage)`.
  4. If `cloud?.isSignedIn` is `true`, `await cloud.saveAll(current)`.
  5. Return `current`.

### How the UI links auth to the mock cloud

Before calling `toggleDayComplete`, client components sync the default client with the stored user:

```ts
const user = loadAuthUser();
mockCloudClient.isSignedIn = user !== null;
mockCloudClient.user = user;
```

The login page does the same after sign in / sign out.

## Phase 4 — Unit tests (`src/lib/progress.test.ts`)

Use `describe`, `it`, `expect` from `vitest`. Build an in-memory `StorageLike`:

```ts
function createMemoryStorage(seed: Record<string, string> = {}): StorageLike {
  const store = new Map(Object.entries(seed));
  return {
    getItem: (k) => (store.has(k) ? store.get(k)! : null),
    setItem: (k, v) => void store.set(k, v),
    removeItem: (k) => void store.delete(k),
  };
}
```

Use a fresh `createMockCloudClient()` per test. Required tests (at least these 4, all passing):

1. **Guest mode:** `toggleDayComplete('day-12', true, { storage, cloud })` with `cloud.isSignedIn = false` → returns `{ "day-12": true }`, storage holds `{"day-12":true}` under `STORAGE_KEY`, and `cloud.remoteData` stays `{}`.
2. **Signed-in sync:** with `isSignedIn: true, user: DEFAULT_MOCK_USER` → `toggleDayComplete('day-13', true, …)` makes `cloud.remoteData` equal `{ "day-13": true }`.
3. **Uncheck keeps others:** seed storage with `{ "day-12": true, "day-13": true }`, call `toggleDayComplete('day-12', false, …)` → result is `{ "day-12": false, "day-13": true }`.
4. **Malformed JSON:** storage seeded with `STORAGE_KEY: "{not json"` → `loadLocalProgress(storage)` returns `{}`.

Nice-to-have (add if quick):

5. `loadAuthUser` returns `null` for malformed JSON; `saveAuthUser(null)` removes the key.
6. Legacy data `{ "day-12": true }` loads unchanged (backward-compatibility guard).

```markdown
# Ticket Pack (BA skill)

## Phase 1 — Intake
- Never assume missing requirements.
- Produce `intent.md` with three sections: **What**, **Why**, **Constraints**.
- List 5–7 sharp **Open Questions** for the Client, covering UX, edge cases, and data sync (guest vs signed-in, offline, legacy data).
- Stop and wait for the Client's answers before Phase 2.

## Phase 2 — Spec & Tickets (after the Client answers)
- Produce `spec.md` with: **Scope**, **Out of scope**, **Data schema**, **UI behavior**.
- Break the work into independent tickets, each under 4 hours.
- Every ticket MUST include:
  - **User Story** — As a <role>, I want <goal>, so that <benefit>.
  - **Acceptance Criteria** — Given / When / Then.
  - **Edge Cases**.
- **Zero-questions test:** a developer could implement the ticket without asking a single question. If not, rewrite it.
```
